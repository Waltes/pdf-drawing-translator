# 1.1.13 —— 通用版不再强制全大写

一条行为改动，影响所有英文译文的观感，所以单独发一版。

## 改了什么

英译方向的译文，**通用版不再强制转成全大写**，改由模型按一般翻译规则输出
（句首大写、专有名词大写、其余小写）。定制版不变，仍按图纸标注惯例全大写。

同一份托盘图纸的对照：

| 原文 | 1.1.12（全大写） | 1.1.13（通用版） |
|---|---|---|
| 地毯托盘俯视图 | `CARPET RACK TOP VIEW` | `Carpet tray top view` |
| 上面宽60mm，下面宽100mm，高度50mm | `TOP WIDTH 60mm, BOTTOM WIDTH 100mm, HEIGHT 50mm` | `Top width 60mm, bottom width 100mm, height 50mm` |
| 焊接几字型挂钩 | `WELDED U-SHAPED HOOK` | `welded U-shaped hook` |
| 90公斤/套 | `90kg/SET` | `90kg/set` |

尺寸、型号、标准号、单位一律不受影响：`M10*70` → `M10×70`，`50*50*2.5mm` →
`50×50×2.5mm`，`PVC`、`DN50`、`Ra3.2`、`4-1/8"` 原样照抄。

## 为什么改

全大写是**机械制图标注**的行业惯例，不是翻译规则。通用版面对的图纸种类远不止
标注这一种：一页产品说明、一段技术要求、一张带英文段落的产品资料，整段大写读
起来全是重音，用户会当成排版事故。

这条规则原本是为定制版那个客户（外贸五金建材，图纸发车间和海外买家）定的，后来
一并作用到通用版上，属于范围放大了。

## 怎么实现

`core/casing.py` 加统一入口 `apply_style()`，内部读 `edition.upper_case()`：

- 定制版（`editions/dynamic.json` 里 `"uppercase": "1"`）：走原有全大写规范，
  含单位小写、客户指定写法，一字未改。
- 通用版（默认关）：走新加的 `plain_case()` —— 只把「整条被写成大写」的条目
  降成正常书写，本来就是混合大小写的原样返回。

散在各处的大小写与「指定译名落笔」也跟同一个开关走：

- `core/translate.py` 两处出口（批量出口、重译旁路）
- `core/dict_engine.py` 词典通道两处

做成统一入口而不是在每个出口写 `if`，是因为译文有四条出口（AI / 词典 / 在线免费
接口 / 重译旁路），逐个加条件必然漏 —— 1.1.12 之前重译那条旁路就漏过大小写和标点。

### 为什么要留 `plain_case`，不能干脆不管

第一版只做了「不干预」，实测同一页里变成这样：

```
POST SQUARE TUBE 50×50×2.5mm              ← 模型/词表给的全大写
Yellow part: removable four-corner posts  ← 模型给的正常书写
```

一份图纸两种风格，比统一大写更难看。根因有两处：

1. 术语库 `glossary.csv` 的英文列本身就是全大写写法（`SQUARE TUBE`、`SCALE`），
   词典通道直拼出来就是大写；
2. 模型的默认倾向是把图纸标注写成全大写。

所以 `plain_case` 只做一件事：**整条字母大写占比 > 0.6 才降级**，其余不动。
降级时保护三类 token —— 含数字的（`DN50`、`M8×30`、`Ra3.2`）、公认缩写
（`PVC`、`HDPE`、`QTY`、`DIA`、`S.S.`、`SUS`、`SCH` 等 60 余个）、无字母的。

`plain_case` 不碰正常书写的句子，所以不是「替模型决定风格」，是「把跑偏的拉回来」。

同时给通用版的系统提示词加了一条 9b：英文按常规书写规则、不要整条转大写，
缩写/单位/型号保持原写法。定制版不加 —— 那边出口会整条转大写，提示词里再要求
小写只是让模型白改一遍。

## 验证

新增 `_std_check.py`：固化在通用版跑，统计「整条被全大写」的条目数并输出逐条译文。
不能用 `_batch.py` 验通用版 —— 它一进来就把 `edition.json` 换成定制版。

| 图纸 | 条数 | 整条全大写 | 排版体检 |
|---|---|---|---|
| 托盘 11-19（4 页） | 29 | 0 | 越界 0、叠字 0、中文残留 0、未译英文 0 |
| 护栏 11-18（8 页） | 83 | 2（都是 `QTY:`，缩写保留） | 越界 0、叠字 0、中文残留 0、未译英文 0 |
| 验收件 | 4 | 0 | 日期 `Date: November 16, 2026`、`Overall length 2790mm`、`Vertical adjustment 100mm`、`Radius 35mm round tube` |

几个典型对照：

| 原文 | 1.1.12 | 1.1.13 |
|---|---|---|
| 材料： | `MATERIAL:` | `Material:` |
| 表面处理： | `SURFACE TREATMENT:` | `Surface treatment:` |
| 边框方管20*20*1.5mm | `FRAME SQUARE TUBE 20×20×1.5mm` | `Frame square tube 20×20×1.5mm` |
| M10*70外六角螺栓 | `M10×70 OUTER HEX BOLT` | `M10×70 outer hex bolt` |
| 数量： | `QTY:` | `QTY:`（缩写保留） |
| 直径10mm钢筋 | `10mm DIA REBAR` | `DIA 10mm rebar` |

定制版回归：托盘图纸 span 40、未译 1（`Omm` OCR 噪声）、全大写行为不变。

## 一处已知的不一致

`尺寸：1.118*3.05米` 译成 `size: 1118×3050mm`，首字母没大写，而 `材料：` 是
`Material:`。原因：前者模型自己给的就是全小写，`plain_case` 只处理全大写的条目，
不动它；后者是从 `MATERIAL:` 降下来的，降级时补了句首大写。

没做全局首字母大写，是因为那样 `：750片` → `: 750 pcs` 会变成 `: 750 Pcs`，
把单位写错比首字母不统一严重得多。


## 顺带

- 使用说明加 9.11 节「译文的大小写」，写明本版不干预及与定制版的差别
