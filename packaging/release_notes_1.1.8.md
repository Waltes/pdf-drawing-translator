# 1.1.8 —— 尺寸和符号不再被"顺手改掉"

## 一、这次修的是什么

客户报：`ø12mm` 译完变成 `@12.00mm`，`25mm` 变成 `25.00mm`。

两处都错了，但原因不在翻译，在**它根本不该被重画**：

| 环节 | 做的事 | 后果 |
|---|---|---|
| 读字 | 把 `ø` 认成 `@`（实测还会认成 `0`、`·`、`.`、`-`） | 符号已错 |
| 出口统一小数位 | 无条件给毫米值补两位小数，`12mm` → `12.00mm` | 文本"变了" |
| 改写 | 只问"变没变"，变了就当译文，擦掉原字重写 | 错字印上图 |

`ø12mm` 是一条纯尺寸标注，本来就不需要翻译。翻译通道原样返回它，是第 2 步
把它变成了"有变化"，第 3 步才把第 1 步的错字印上去。三个环节各让一步，
最后以客户看不懂的方式出现。

## 二、改了什么

**1. 小数位只在真换过单位时统一**

原来无条件跑，连没换算过的 `25mm` 也补成 `25.00mm`。现在只有含英制、真的
做过换算的条目才走这一步。同时整数一律不补尾零 —— `50` 和 `50.00` 在工艺上
是两个精度等级，补上去等于替客户加严了公差，这也与提示词里"不补尾零"这条对齐
（原来两处规则互相打架）。

**2. 改写前比"内容"，不再比字符串**

新增"同一内容"判据：只抹平数字尾零和空白，符号差一个都算不同（`公斤` ≠ `kg`、
`@` ≠ `ø`）。内容没变的条目一律不重写。`4-1/8"` → `104.78mm` 这种真换算不受影响。

**3. 尾零收紧认得非 ASCII 前缀**

`ø12.00mm`、`Ø12.00mm` 原来收不回来 —— 正则的前置断言用了 `\w`，而 `ø`、`Ø`
在 Unicode 里算 `\w`，被当成"紧贴字母"。改成只挡 ASCII 字母数字后，
`ø12.00mm` 能正确收回 `ø12mm`。

**4. 单字母代号不送去翻译**

`R5`、`M8×30`、`H7` 这类不送模型。送去就可能被展开成缩写或改大小写，
而图上 `R5` 就是半径 5。

**5. 单位后缀不再算"有字母"**

`25mm` 里的 `mm` 是单位不是词。原判据只看"有没有拉丁字母"，纯尺寸标注在
英译中方向会被当成英文送进模型 —— 那条路上同样会出现 `ø` → `@`。

**6. 纯尺寸不再进未译清单**

清单上写"25mm 未译"只会让人以为工具没干活。

**7. 小写 `ø` 也认作直径**

以前只认 `Ø ⌀ φ Φ`，而真实图纸上最常见的是小写 `ø`。

## 三、实测

| 项目 | 结果 |
|---|---|
| `ø12mm` / `Ø12mm` / `±0.5mm` / `90°` / `R5` / `M8×30` | 全部原样保留 |
| `4-1/8"` → `104.78mm` | 换算照常 |
| `3公斤` → `3kg` | 译出，且不再带 `.00` |
| 客户图纸（2 页 7 个视图标题） | 重心误差 0.0pt，同类同字号 18.95 / 18.97pt |
| 全图搜 `.00` 与 `@` | 0 处 |
| 自检 | 53 项全部通过（新增 4 项） |
| 排版测试 / 计量测试 | 6 种窗口全过 / 25 项全过 |

新增的 4 项自检：坏符号的尺寸标注不会被重画、整数尺寸不再补两位小数、
有可译内容的照常写、纯尺寸不算漏译。
