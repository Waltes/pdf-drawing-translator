# 1.1.9 —— 读不出的符号，按形状找回来

## 一、这次修的是什么

客户报：源图 `流水孔 ø12mm` 译成 `Weep hole 12 mm`，**直径符号整个没了**。

1.1.8 保住的是「不需要翻译、也不该重画」的那类标注。这一条不一样 —— 它**真要翻译**
（`流水孔` → `Drain hole`），所以必然要重画，而重画的前提是先把符号读出来。

问题就在读这一步。同一个 `ø` 换着法子试：

| 试法 | 读到的结果 |
|---|---|
| 整页 300 dpi | `流水孔12mm` —— 符号被丢弃，不留痕迹 |
| 整页 800 dpi | `流水孔012mm` —— 认成了数字 0 |
| 裁出来单字送识别 | 空结果；连着邻字一起才读到 `01` |

识别模型基本不认识这个符号，调倍率、换预处理都救不回来。

翻译模型本身是可靠的 —— 给它 `ø` 它就保留，不给也不凭空补：

```
流水孔ø12mm  →  Weep hole ø12mm
流水孔12mm   →  Weep hole 12mm      ← 原文里没有，模型不猜
流水孔@12mm  →  Weep hole @12mm     ← 读错了它也照抄
```

所以缺口只能在读字这一端补，而且是**绕开识别、直接看形状**。

## 二、怎么认出来的

直径符号是一个闭合圆环被一条斜线分成两半。这个结构在字形里很独特，给了三个
别人没有的特征：

- **内部两个洞** —— 数字 `0`、字母 `o` 只有一个
- **两洞质心连线是斜的** —— `θ` 和 `8` 是上下 90°，`φ` 和 `%` 是左右 0°
- **高度只有数字的六到八成** —— 它是小写字母，只占 x-height（大写 `Ø` 顶到 1.0，
  同样认）

判定必须放在 8 倍放大下做。低倍时笔画只有两三个像素宽，描边的字一闭运算就糊成
实心，洞全没了 —— 实测 4 倍直接判成「洞数 0」。放到 6~12 倍，同一个符号的洞数和
角度完全稳定（116~122°）。

所以流程是两段：低倍快速找出「尺寸和比例像个符号」的候选，只对候选按 8 倍重渲染
一次做精判。一页上大部分标注连候选都没有，一次多余渲染都不触发。整条里一个数字
都没有的直接跳过 —— 直径符号永远贴着数字写。

补回去的位置：符号簇有自己的横坐标，把整行文本按字符宽度铺开，离它最近的那个字符
就是它该待的地方。只在那个字符是数字或字母时才插；落在汉字上说明对齐估偏了，
宁可不补。

## 三、两条硬规矩

**只认这一种符号。** `°`、`±`、`×`、`□` 的形态特征弱得多，硬认会把数字读坏。
认错一个符号等于把客户的孔加工错，宁可不补。

**宁缺勿滥。** 下面这些一个都不许被认成直径：

| 输入 | 结果 |
|---|---|
| `8mm` | 不补（数字 8 两洞但上下排列） |
| `100%` | 不补（两洞左右排列） |
| `日` `回` `四` | 不补（两洞同心或左右） |
| `θ5` | 不补（两洞上下） |
| `Q12` | 不补 |

大写补大写、小写补小写：`Ø50` → `Ø50`，`ø12mm` → `ø12mm`，不替客户改大小写。

## 四、顺带修的一处排版

补上符号之后这条标注变长，暴露出一个旧问题：`流水孔ø12mm` 原地折成两行能放到
12.51pt（够类字号的九成，于是停手，不再试加宽），而沿基线加宽其实**一行**就能
放到 13.54pt —— 差 2.5% 的字号，却把原本一行的标注拆成两行，还压到下面那条
`Red part` 上。

现在折行本身要打折（`typography.WRAP_COST = 0.90`）：单行只让一成以内的字号
就守住单行，折行能换来超过一成的字号才折。这一条对所有标注生效，不只是标题。

## 五、实测

| 项目 | 结果 |
|---|---|
| 客户图纸 3 页，每页一处 `流水孔 ø12mm` | 全部 `Drain hole ø12mm` 单行输出 |
| 合成样张 12 组正反例 | 12/12 通过（`ø` `Ø` 认出，`8` `%` `日` `0` `08` `Q12` `θ` 不认） |
| 新储物柜图纸（回归） | 7 个标题重心不变、同类同字号 18.95 / 18.97pt，无多余符号 |
| SledBox、护栏托盘（回归） | 无 `ø`/`@`/`.00` 误加 |
| 自检 | 55 项全部通过（新增 2 项） |
| 排版测试 / 计量测试 | 6 种窗口全过 / 25 项全过 |
| 处理耗时 | 3 页图纸 11.3 s（优化前 12.4 s，检测层净开销可忽略） |

新增的 2 项自检：读不出的直径符号能从字形找回来、数字与百分号不被当成直径符号。

## 六、已知局限

- 只认直径符号。角度 `°`、公差 `±`、乘号 `×` 若被 OCR 丢弃，目前仍会丢。
- `Ø` 与相邻字符粘贴紧密时（`Ø0` 这种）可能粘连成一个簇而漏判；`Ø12` 正常。
- 文字层（非转曲）PDF 不缺这一步 —— 它是矢量文字，符号在文本里，不走 OCR。
- 老账不变：两个路径各有一套排版（文字层未接占用图）、引线不重画、
  `tools_synth_check.py` 的「E 组字高」测量恒为 0（改动前后一致，非本版引入）。
